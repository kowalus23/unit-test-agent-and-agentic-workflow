# Threat model: unit-test agent

The agent reads untrusted content (the pull request's code and comments), runs untrusted code (the PR's tests) and needs a model API key. The design follows the *Rule of Two* for agents: no job combines untrusted input, a secret **and** the ability to change the repository.

| Job | Untrusted input | Secret | Can change the repository |
|---|---|---|---|
| plan | reads the diff (no code runs) | no | no |
| prepare | runs `prisma generate` on the PR (loads its `prisma.config.ts`) | no | no |
| agent | yes; PR code runs only inside the agent's sandbox | model key only (one step) | **no**: read-only token, artifacts only |
| verify | runs the PR's code and the agent's tests, unsandboxed (passwordless sudo) | no | no, but its `final.patch` and `verdict.json` feed apply |
| publish | renders artifacts (no model, only base-branch code) | no | `pull-requests: write`, used for one sticky comment |
| apply | `final.patch` and `verdict.json` from a job that ran PR code, re-checked by the base-branch guard | no | one commit of test files on the PR branch, on a label (triage access or higher; only the owner here) |

## Threats and mitigations

| # | Threat | Mitigation | Enforced by | Evidence |
|---|---|---|---|---|
| T1 | Prompt injection in code, comments, file names or tool output steers the agent | Repository content is data (agent rules). The plan carries fixed signal strings, never PR text. Paths are restricted to `[A-Za-z0-9._@/-]`. Injection signals are flagged and shown in the report. | `scripts/agent/plan.ts`, agent definition | Red-team [#20](https://github.com/kowalus23/unit-test-agent-and-agentic-workflow/pull/20): Haiku reported the injection and did not act on it |
| T2 | The agent edits production code, CI, dependencies or its own configuration | Write allow-list for test files. Deny rules for `.claude`, `.github`, `scripts`, `backend/src`, `backend/prisma`. A PreToolUse hook that denies by default and blocks the call when it crashes or times out (`onFailure: "block"`). A patch guard (no deletes, renames, mode changes, symlinks, submodules or binaries; size limits) runs in verify and again in apply, from a fresh base checkout. The apply run is the authoritative check, because apply runs no PR code. | `.claude/policy/*`, `.claude/hooks/guard-tool-use.ts`, `.claude/lib/patch-guard.ts`, `apply-commit.ts` | `patch-guard.test.ts`, `guard-tool-use.test.ts` (malicious patches, symlink writes, command chaining, `onFailure`). Local check with CLI 2.1.308: a hook that exits 1 let `Read` run without `onFailure`, and the call was denied with it. |
| T3 | A PR changes the agent that reviews it (`CLAUDE.md`, `.claude/`, `.mcp.json` at any depth) | Agent configuration, scripts and the CLI lockfile come from the **base** commit. After the dependency install, every `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.claude/`, `.mcp.json` and `.claude.json` in the PR checkout, including `node_modules`, is removed. The base branch's `.claude/` and root `CLAUDE.md` are then copied in. Config changes raise a flag. | `unit-test-agent.yml` (restore step), plan flags | Workflow design; `agent_config_changed` flag. This holds only for PRs that do not edit the workflow (see residual risks). |
| T4 | Key exfiltration by code that runs next to the key (tests, dependency CLIs, config files) | Commands the agent starts run under `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` in bubblewrap: the test runner and type checks, which means the PR's tests. Credentials are removed from their environment and they get a separate PID namespace. Their network goes through the CLI's proxy, which allows no domains by default; `agent-settings.json` does not set this and no test exercises it. The agent process gets an allow-listed environment and no GitHub token, and `git` gets no credentials. Sudo is removed before PR code runs. No PR code runs outside the sandbox in this job: packages are installed with scripts disabled, and the Prisma client is generated in the prepare job, which has no secrets. | `.github/actions/agent-runtime`, `unit-test-agent.yml`, `run-agent.ts` (allow-listed environment) | Run logs show PID isolation and the sudo removal ("bubblewrap 0.9.0 works with an isolated PID namespace", "sudo removed for runner"). Network blocking is not shown. |
| T5 | The agent claims passing tests that do not pass, or writes weak tests | Numbers come from verify only: baseline vs patched suites, typecheck, discovery, 3 shuffled stability runs and no coverage drop, decided per package. The agent's result must match a JSON schema. Verify guards against a mistaken or weak agent, not against hostile code: the PR's code and the agent's tests run in the same job and as the same user as `verify.ts`, and could alter its output. Whatever verify reports, apply commits only regular test files that pass the base-branch guard. | `scripts/agent/verify.ts`, `.claude/lib/json-schema.ts`, apply job | Runs where the agent could not execute tests reported `not_run`, and verify still decided on its own |
| T6 | Tests pin a bug or rewrite human expectations | "Never pin a bug" rule, with `suspected_bug` findings. Changed human assertions are detected and reported (`changed_expectations`); setup-only edits are reported separately. A pattern check rejects `.only`/`.skip`/`.todo`/`.fails`, `xit`/`xdescribe`, snapshots, literal `child_process` imports and literal credential reads (`process.env.ANTHROPIC_*`, `GITHUB_*`, `GH_*`, `ACTIONS_*`) in added test lines. That check is a lint against mistakes and easy to bypass; credentials are kept away from tests by the sandbox and by verify having no secrets. | agent rules, patch guard, `forbiddenTestContent` | Sweep and feature runs: bugs were reported, and no human assertion changed |
| T7 | The PR comment becomes an exfiltration or phishing channel | The report is rendered by code from the artifacts. Model text and every structured field from `verdict.json` and `metrics.json` are reduced to plain text: no links, images, HTML or mentions, `<` and `>` escaped, length caps. Numbers must be finite, and paths cannot leave their code span. Only GitHub Actions run URLs are linked. | `scripts/agent/render-report.ts` | `report-and-verdict.test.ts`, including a tampered verdict; the red-team report contains no payload text |
| T8 | Race: tests applied to a different commit than the one verified | Apply finds the run verified for the **current** head, re-runs the guard, checks the verdict's SHA and commits with `expectedHeadOid` | `unit-test-agent-apply.yml`, `apply-commit.ts` | `buildCommitInput` tests (stale or mismatched patches refused) |
| T9 | Loops and noise: the agent reacting to its own commits, duplicate comments | A `Unit-Test-Agent:` commit trailer makes the next plan skip. One sticky comment is updated in place, and a skipped run never overwrites the report. | `plan.ts`, publish job | PR #19: the agent skipped commit `3e9c06b` and the report was kept |
| T10 | Supply chain of the workflow itself | Enforced: actions pinned to full SHAs and GitHub-owned actions only (repository settings), `persist-credentials: false`, `permissions: {}` by default, and actionlint, zizmor (pedantic persona) and shellcheck in CI. Practices that nothing re-checks: npm installs with `--ignore-scripts`; lockfiles resolved once with `npm install --before=2026-10-16`, with documented exceptions; Dependabot with a 7-day cooldown that proposes no npm or Actions majors. The pinned Claude Code CLI in `.github/agent-runtime` is updated by hand. | repository settings applied by `scripts/bootstrap-repo.sh`, `ci.yml`, `dependabot.yml` | `workflow-lint` job |
| T11 | Runaway cost | Per-tier `--max-turns` and `--max-budget-usd`, at most one escalation (per-run ceiling: $2.75 from S, $6 from M, $4 at L), job timeouts. Runs are skipped for docs-only, draft, bot and fork PRs and for the agent's own commits. A workspace spend limit caps the key. | `test-policy.json` routing, `run-agent.ts` (`nextTier`), workflows | Typical runs: $0.009 (tier S) to $0.40 (tier L) |

## Residual risks (accepted, documented)

- **Workflow changes.** Anyone with write access can change the workflows in a same-repository PR, and `pull_request` runs the workflow file from the PR's merge commit. T3, T4 and the apply checks therefore hold only for PRs that do not edit `.github/workflows/`.
- **Environment and base branch.** The `unit-test-agent` environment has no deployment-branch policy or required reviewers, so any workflow on any branch can read the key. The trusted base is the branch the PR targets, and the ruleset protects only `main`.
- **No second reviewer.** CODEOWNERS is advisory here (code-owner review is not required), and a solo repository cannot require a second reviewer.
- **Shared machine.** The agent job runs the PR's tests on the same virtual machine as the process that holds the model key, inside the sandbox. A sandbox escape would reach the key. The removed sudo and a spend-limited key bound the damage.
- **Verify is not isolated.** Verify runs PR code unsandboxed and with sudo. It holds no secrets, and apply re-checks everything it commits.
- **Public artifacts.** Artifacts of a public repository can be downloaded by signed-in users while they are retained (1–7 days). No transcripts are uploaded.
